## R14 — PROPOSED, needs Jonathan's yes before anything is deployed
Found by testing the engine on flat, noisy elevation data like the Arkansas Delta: with ~0.2 m of total relief across the parcel the engine published 2–5 short wiggly swales (12–19 m) that pass R1–R13, because slopes measured from 0.1 m elevation steps and noise look like 2–3% slope. R14: if the 5th–95th percentile elevation relief inside the property is below 1.0 m (`LIMITS.minReliefM`), publish no swales and state why; the zero-swale reason reuses the page's existing key (no new on-screen text). The engine always reports `evidence.terrain` = `{reliefM, p05M, p95M, minReliefM, gate, swalesSuppressedByGate}` so each browser run shows what the gate suppressed. `input.minReliefM:0` turns it off. 1.0 m is a starting value chosen from simulation, not from Arkansas measurements — read `terrain.reliefM` from the Arkansas runs and tune. If Jonathan says no, set `minReliefM:0` (one line) and R14 is gone.

## What the engine does (spec: `governing/EARTHLINE-PROPERTY-SWALE-ENGINE-SPEC.md`)
Slope ≤ 4% mean and no 5-sample median above 4% · level within 0.3 m · ≥ 12 m · spacing ≥ 4.572 m · ≥ 10 ft from roads, driveways, parking, buildings and the property line · ≥ 18 m from mapped water and wetlands · out of modelled washes (+3 m) · inside the boundary · tortuosity ≤ 2.15 · mean slope ≥ 0.2% · fail closed. Exclusions come from Mapbox Streets vector tiles fetched directly at zoom 15 for the property + 60 m and decoded in the page (never from what is on screen), plus manual no-build polygons and, in Vermont, the E911 driveway and VCGI building geometry the page already loads. Every proposed swale is then re-measured against the exact vector geometry; any swale closer than required is dropped. A missing, empty, failed or undecodable tile halts the run; only a fully decoded set with nothing mapped can say "screened-clear".

## What each browser run records (per site, per run) — read these
`engine16600`: `terrain` (R14 relief and what it suppressed) · acquisition status/tier/feature counts/tiles · engine vs published swale counts · rejections by rule · `coverage` (share of the property removed by built / water / channel / slope) · audit (rejected, minimum clearances) · parameters (channel threshold, grid) · timing · determinism hash and stable ids. Plus `closestPairM` (must be ≥ 4.572), `steepestSwalePct` (must be ≤ 4), `drawnLivingSwales` vs `shownSwales` vs published, `sameEngineHashBothRuns` / `sameStableIdsBothRuns`, `independentExclusionCheck` (Node re-measure with a different decoder; `violations` must be 0), `sensitivity` (same grid re-run at five channel definitions; publishes nothing), and the `fail-closed` row (direct tile request blocked: expect `engine16600.verified:false`, zero swales shown).

## Decisions and approvals Jonathan needs (none are applied silently)
- **Channel definition (R8)** controls how much land is excluded as "modelled wash". Default here = the page's own protected-channel threshold (3.0 × `streamThreshold()`, same as the existing no-build mask) on the page's filled-terrain accumulation. The `sensitivity` table shows swale count and buildable share at 0.78×, 1×, 3×, 5×, 10×. Choose from those numbers.
- **Wording.** No new on-screen text. On failure the page shows its existing "Analysis stopped: <code>" with the new code `clean-engine-exclusion-check-failed`. The spec's "Road and water check unavailable · try again" and the "No qualifying swales…" finding are NOT shown; they need your approval first. The old "Coverage evidence" panel (old engine's statistics) now shows its "pending" text for Property; it needs new approved content or removal.
- **Assumed road widths** (half-width by Mapbox road class: motorway 9 m … path 1.5 m, driveway 3 m) and **all waterway classes get the 18 m setback** (ditches and drains too), as R7 is written. Both are provisional and listed in the bridge file.
- **Capture figures** in the report/table now mean the contributing area summed along the swale; the old engine used a different measure, so numbers will differ.
- **Display ids** stay B1…Bn (ordered by elevation); the geometry-hash id is kept as `stableId` in the data.
- **Not yet wired:** hydrologic soil group (drawdown reports "not assessed", never assumed to pass) and bare-earth terrain (still Mapbox terrain-RGB, so wooded land reads steep and yields few swales, with reasons).

## One thing to read in the first Arkansas run
When R14 refuses a flat property, the page's existing zero-swale reason key is chosen by the adapter from the engine's rejection counts (`no-suitable-slope-corridors` or `all-candidates-excluded`). On flat noisy land that choice can land on "all-candidates-excluded", which may read wrongly for a flat property. The test records the on-screen status text (`statusText`) for every run; check it. Not changed here because it would alter `index.html`; if the text is wrong, the fix is one line in `tools/adapter-16600.js` (count R14 on the slope side).
